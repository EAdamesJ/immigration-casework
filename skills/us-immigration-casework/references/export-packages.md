# Reviewable export packages

Prepare one curated report rather than dumping a case folder. Use `assets/export-packet.json`: non-sensitive case ID, descriptive title, language, plain-text sections. Include the requested review, evidence status, document/page references, unresolved questions, actions, deadlines with their actual sources, source ledger and material limitations. Add the DS-160 worksheet findings, refusal analysis or OCR review ledger only when relevant; these modules do not automatically ingest each other or infer facts.

`preparation.py export` produces Markdown, self-contained escaped HTML, JSON and a ZIP by default. Optional `--formats md html json pdf docx` adds PDF via ReportLab and DOCX via python-docx, installed separately by the host. The default exports use Python's standard library. Missing optional dependencies fail explicitly. PDF embeds ReportLab's bundled Vera fonts and limits input to Western text: unsupported characters fail rather than silently disappearing; use DOCX/HTML or a host renderer with appropriate fonts for native-script names. Render and visually inspect every page of actual PDF/DOCX deliverables before delivery. Use source file hashes and extracted text checks in addition to layout review.

Run with a new output directory outside Git. Outputs are private on POSIX (folder 700, files 600); Windows ACLs are the user's/host's responsibility. All rendered reports display DRAFT/BORRADOR and review-required language. JSON forces `status: draft` and `submitted: false`. Never relabel the package as an official DS-160, a signed application, a certified translation or submitted evidence. No output is automatically sent anywhere.

Only `--attach /explicit/file` adds an attachment; no recursive collection. Supported attachments are PDF, PNG, JPG, JPEG, TXT, JSON and DOCX, at most 25 MB each and 100 MB total. Attachment names become `attachments/001.ext`, etc., in the same explicit order; map these paths to source document IDs in the report before sharing. The manifest records each file's path, bytes and SHA-256; the ZIP contains the report files, attachments and manifest, never itself. Preserve originals separately. Verify the manifest before relying on a transferred archive.

The ZIP is **not encrypted or redacted**. Review recipient, purpose, authority, unnecessary identifiers, metadata, signatures, raw OCR and attachments before sharing. Plaintext patterns/redaction helpers cannot guarantee removal of private data; do not label a package safe for public posting. Do not export credentials, application security answers or unrelated third-party records. Sharing/submission requires the host's appropriate authorization; creation is not transmission. On failure the newly created partial export is removed; existing outputs are never overwritten.
