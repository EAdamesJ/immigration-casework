# Calendar and notifications

Keep government deadlines, appointments, internal preparation targets and reminders distinct. Never calculate a legal deadline from an OCR date, a generic processing estimate, a calendar-month assumption or a guessed service rule. A `documented_deadline` entry requires actual source inspection, document ID/page, checked date and the specific basis. These are recorded attestations, not automatic legal validation. Verify jurisdiction, local cutoff, delivery rule, extensions and the notice separately; do not treat the generated event as legal advice.

Copy `assets/calendar-events.json` into a private workspace and replace synthetic facts. Each event has case/event IDs, revision, kind, neutral summary, confirmed/tentative/cancelled status, start/end and explicit all_day. Timed entries require ISO timestamps with seconds, explicit offset and matching IANA timezone. This rejects floating times, wrong offsets and daylight-saving gaps. Ambiguous fall-back times need the chosen offset. All-day end dates are exclusive; they do not mean an invented midnight deadline. The helper calculates no legal cutoff. All-day alarms are blocked until a separate reminder time is confirmed. Windows or minimal systems may need the optional `tzdata` package; UTC works where that zone is available.

`agenda.py` exports RFC 5545 `.ics` in a new private folder. It preserves stable UID and increasing SEQUENCE, escapes text, folds at 75 UTF-8 octets, uses CRLF and exports timed entries in UTC. It omits parties' names, legal history, attachments, attendees, links and detailed source text; summaries must also be neutral. `CLASS:PRIVATE` is a calendar hint, not access control. Import behavior, duplicate/update/cancellation handling and alarms vary by client: inspect the imported event. Exporting ICS is not importing or activating notifications. A cancelled export does not delete an existing provider event.

Timed entries accept up to five explicitly selected reminder offsets, 0..40320 minutes before start. These are operational choices, not a promised delivery schedule. ICS includes only display alarms; no mail or executable alarm is generated. Calendar clients can change or ignore alarms. Native Google/Outlook create adapters use their supported reminder fields; verify the final event's actual reminders in the provider. The Google adapter can carry multiple popup reminders; Outlook supports one and timed events only.

Notifications use the local authorization-bound queue. `not_before` is a dispatch eligibility time, not an installed scheduler. `status` lists due authorized actions; nothing wakes itself up. Run a deliberate host job or install an actual automation only when requested, recording its returned ID, timezone, enabled state and next execution if available. v2.0's adapter supports one-time self reminders; recurring visa-bulletin monitoring remains a separately configured host workflow. It does not automatically monitor changes or send alerts because the skill was installed.

Keep reminders generic, e.g. “Review case task C001,” with no passport, A-number, medical details or refusal history in subjects, calendar titles or lock-screen alerts. Resolve any professional recipient using connected contacts/records and the user's instruction; syntax is not identity. Draft review messages before sending. A notification does not replace case responsibility, source checking or an agency deadline. If a provider is unavailable, leave a local draft/ICS and name the exact blocked service, rather than promising delivery.

Calendar source: [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545), sections on content-line folding, TEXT, DTSTART/DTEND, UID, SEQUENCE and VALARM; checked 2026-10-31. Recheck relevant errata/client behavior before adding new features such as recurrence or invitations.
